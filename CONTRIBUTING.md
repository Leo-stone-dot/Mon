# Contributing

Mon is an independently maintained reference fork rather than a collaborative
upstream project. **Pull requests are not accepted.** Unsolicited patches may be
closed without review.

## Fork and AI-assisted development

Fork the repository and make the changes you need in your own fork. The intended
working model permits AI-assisted development, but the fork owner remains
responsible for reviewing generated changes, testing behavior, protecting
credentials and user data, and complying with dependency licenses.

Keep upstream Amethyst attribution and the repository license intact. Do not
present a derived fork as supported or endorsed by either Mon or upstream
Amethyst.

## Issues are observations

GitHub issues may record reproducible bugs, compatibility observations, or
feature ideas. They are not a support queue or roadmap. There is no SLA for
triage, response, resolution, or release, and an issue may be closed without
implementation. The maintainer may use an observation as input for later work.

Use the supplied issue templates and remove secrets and personal information
before posting. For security observations, follow [SECURITY.md](SECURITY.md):
this repository has no private reporting channel and accepts only public issues.

## Local changes

For source builds and signing behavior, see [README.md](README.md). For
configuration behavior, see
[Configuration Files](docs/configuration-files.md). Run the checks appropriate
to your changes in your own fork; passing checks does not create an obligation
for this repository to accept or distribute the result.
